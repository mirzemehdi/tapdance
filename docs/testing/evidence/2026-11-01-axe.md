# Evidence: AXe iOS backend — 2026-11-01

Real simulator, no mocks. Same Mac as [2026-11-01-local-ios.md](2026-11-01-local-ios.md).

## Setup

- AXe 1.8.0 from its official release tarball; the archive's SHA-256 matched the one in AXe's Homebrew
  formula (`87eb09cd…ea7f`). Installed to `~/.tapdance/tools/axe`, frameworks ad-hoc signed.
- Simlock switched to Xcode's default device set (`drivers.ios.deviceSet default`), after deleting
  the simulators in Simlock's own set with Simlock's documented `nuke --delete-devices`. Switching
  while that set still held a simulator turned iOS off; `worker install --ios-backend axe` now refuses
  in that state and prints the migration steps.
- Tapdance config (scratch `TAPDANCE_HOME`): `ios.uiBackend: "axe"`, `ios.axePath` set.

## What ran (CLI, iPhone 16, iOS 26.5, `examples/ios-demo`)

`device lease` → `app install TapdanceDemo.app` → `app launch dev.tapdance.demo` → `record start` →
`ui inspect` (text fields with ids `email`/`password`, button `sign-in`) →
`ui type "qa@tapdance.dev" --text Email` → `ui type "secret123" --text Password` →
`ui tap --text "Sign in"` → `ui wait --text "Welcome, qa@tapdance.dev"` (found after 434 ms) →
`screenshot` (1179×2556 PNG showing the welcome line) → `record stop` (390 KB MP4) → `app list` →
`device release`.

## Bugs found by the first run, fixed before this one

- `describe-ui` right after launch failed with "No translation object returned for simulator": the
  app's accessibility tree was not ready. The backend now retries for up to 8 s.
- `tap --label Email` missed the SwiftUI text field, which has no label, only a placeholder. Text
  targets are now resolved against AXe's tree (label, id, placeholder, value; interactive elements
  first) and tapped at the element's centre.

## Not covered

AXe through a gateway or the worker guard (AXe must run on the Mac hosting the simulator), gestures
beyond swipe, and alerts.
