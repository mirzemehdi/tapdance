# Evidence: Android emulator on macOS — 2026-11-01

Real emulators, no mocks. Same Mac as [2026-11-01-local-ios.md](2026-11-01-local-ios.md).

## Setup that made Android work

Simlock needs the Android command-line tools. Installed
`commandlinetools-mac_arm64-15859902_latest.zip` from dl.google.com after checking its SHA-256
against Google's published value (`835b62a2…02c4e`) into `~/Library/Android/sdk/cmdline-tools/latest`
(sdkmanager 22.0; the bundle also ships Google's Android CLI 1.1.16717390). JDK: JetBrains Runtime 17.
`tapdance worker restart`, then `tapdance doctor` reported Android ready (emulator 36.5.11, 0/2
running). Simlock created its own emulators from the installed `android-34` arm64 images; the
developer's own AVDs were untouched.

## What ran

1. **CLI, Settings app** — `device lease --platform android --device "Pixel 8"` (77 s: create + boot,
   Android 34), `app launch com.android.settings`, `ui inspect` (30 elements with resource ids),
   `record start`, `ui tap --text "Network & internet"` (diff returned), `ui wait --text Internet`,
   `ui key back`, `ui swipe --direction up`, `ui type`, `ui key enter`, `screenshot`, `record stop`
   (MP4), `logs --app`, `logs --crash`, `app stop`, `artifacts`, `device release`.
2. **Google Play image** — `device lease … --image-tag google_apis_playstore` (104 s): Play Store
   (`com.android.vending`) launched to its sign-in screen; screenshot taken. Play Billing itself needs a
   signed-in license-tester account and a build on a Play testing track; not exercised.
3. **Browser viewer on Android** — the Play emulator streamed live in a real browser; Home from the
   viewer went to the launcher; a click on the Play Store icon opened it; the viewer's Screenshot and
   Start/Stop recording buttons produced a PNG and a 0.77 MB MP4.
4. **Custom APK** (`examples/android-demo`, built without Gradle, 12.7 KB): upload + install, launch,
   inspect (Email, Password, Sign in), `ui type … --text Email/Password`, `ui tap --text "Sign in"`,
   `ui wait --text "Welcome, ada@example.com"` (34 ms), screenshot.
5. **MCP over stdio** — `TAPDANCE_IT_PLATFORM=android … TAPDANCE_IT_APP=…/TapdanceDemo.apk` integration
   test passed (full loop incl. recording, logs, crash logs, `execute_tool asc --version`, release).
6. **Google's Android CLI through Tapdance** — `tapdance android -- --version` works. The first
   `tapdance android -- layout --flat` on the leased emulator answered "Multiple devices are currently
   online": the CLI honours Simlock's adb server port but **ignores `ANDROID_SERIAL`**, so nothing ran
   against the wrong device. Tapdance now appends `--device=<leased serial>` when the subcommand's own
   `--help` lists `--device`. Re-run on a fresh `Pixel 8` lease with the demo app open:
   `tapdance --json android -- layout --flat` ran `layout --flat --device=emulator-5586`, exited 0 and
   returned the demo app's window (Email, Password, Sign in). `android -- docs --help` got no
   `--device` appended.

## Gaps found, then fixed and re-checked on the same Mac

- `app list` returned an empty list. Re-run: Android listed `Demo (dev.tapdance.demo)`, iOS listed the
  demo app.
- `logs --app <id>` silently fell back to all logs when the app was not running. It now labels the
  reply "logcat (all processes)" and adds a note; re-run with `com.example.notrunning` showed the note,
  and with the running demo app returned only its lines.
- The OS version column in `tapdance devices` was empty on both platforms: Simlock 0.4 lists runtimes
  as plain strings. Now `OS versions: 31, 33, 34 (default 34)` for Android and `18.5, 26.5 (default
  26.5)` for iOS; models with no installed image are no longer listed.
- `devices` reported Simlock's `used` count (devices that exist, shut-down ones included) as
  "leased". It now counts leases.
